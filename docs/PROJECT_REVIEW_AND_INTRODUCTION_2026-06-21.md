# PowerRAG 项目介绍与复盘报告

> 版本日期：2026-06-21

## 一句话介绍

PowerRAG 是一个本地优先的 RAG / GraphRAG 知识工作台，用于把 PDF、JSON、文本、技术文档、项目资料等非结构化资料转化为可检索、可追溯、可评估的知识系统，并通过标准 RAG、混合检索、知识图谱、社区摘要、全局搜索和 Electron 桌面端提供完整的问答与分析能力。

## 项目定位

项目要解决的问题是：当资料规模变大、来源复杂、问题需要跨文档或跨分区综合时，单纯把文本交给大模型或只做 top-k 向量检索，容易出现召回不全、证据断裂、关系缺失和回答不可审计。

PowerRAG 的定位是：

- 面向本地资料的知识库构建系统。
- 面向复杂问题的 RAG / GraphRAG 实验平台。
- 面向项目汇报和研究验证的可视化控制台。
- 面向真实使用的桌面端本地工具。
- 面向持续迭代的工程化原型。

## 当前能力

- 文档接入、解析、切分、入库和索引。
- 标准 RAG、混合检索、GraphRAG 和全局社区摘要检索。
- 知识图谱抽取、图谱存储、社区划分和图谱问答。
- 引用、证据、route、capabilities、graph quality gate 和 triage 记录。
- Electron 本地桌面壳，支持后端自启动和受限本地文件选择。
- 通用 PowerRAG 一键流程，面向工程资料和项目资料的端到端演示。

## 阶段复盘

已经完成的关键工作：

1. 搭建 RAG 控制台主线。
2. 拆分后端、前端、存储、检索、编排、图谱、评估等模块。
3. 增加 GraphRAG API、社区检测、社区摘要和全局搜索。
4. 加入 GraphRAG triage 与评估机制。
5. 增加 Electron 桌面端。
6. 对前端导入、构图流程、运行日志和大图渲染做了工程化处理。

主要工程原则：

- 所有 RAG 和 GraphRAG 输出最终都要能回到原始文本证据。
- 全量问题不能只依赖 top-k，需要按资料分区或业务结构做覆盖分析。
- 图谱关系只能辅助召回和组织证据，不能替代原文证据。
- 前端展示必须和后端数据能力区分开，大图可以降级展示，但完整数据应保留在后端或导出文件中。

## 后续方向

- 固化通用 PowerRAG 操作流程。
- 加强图谱抽取前后的专业结构注入。
- 完善评估集、回归用例和质量门。
- 将前端从单文件控制台逐步拆分成更可维护的模块。
