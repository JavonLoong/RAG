# FMEA 正文发布与三格式交付设计

**状态：APPROVED。** 用户于 2026-09-04 确认设计与实施计划，开始按任务实施；设计获批不代表代码已实现。

日期：2026-09-04。基线：`feat/interface-output-v1` / `9fca984e`。

前置设计：[完整 FMEA 产品](2026-08-27-full-fmea-modular-product-design.md)。

## 1. 范围与现状

本次仅补齐 FMEA 已批准正文的发布与交付，不新增上游检索算法、不重做评分/传播算法、不扩展账户系统或工作台。

代码核对结果：

- `fmea_application/governance_service.py` 的 `RevisionGovernanceService._snapshot()` 调用 `_inputs()` 后丢弃返回值；行、风险、传播只输出 ID、版本、哈希。
- `GovernanceInputs` 已提供受来源证明保护的行、风险、传播和 EvidencePack。不能把普通调用方字典视为同等权威数据。
- `NormalizedFmeaSnapshot` 已支持不可变 JSON 结构和安全限制；三格式适配器可携带丰富字段，但现有 Office 类型表不能自动等同于易读工程报告。
- `_write_publication()` 已原子写入快照、发布记录及审计链；已有哈希链验证不能代替“正文与已批准源内容一致”的验证。
- Phase 4 完整离线链路已经存在。本次扩展其断言，不另起一套伪造成功的演示链路。

## 2. 方案选择

| 方案 | 优点 | 代价与结论 |
| --- | --- | --- |
| 发布时核对批准版本并物化正文 | 复用现有治理、存储和导出链路；新内容有固定快照 | 需要正文绑定、原子提交和失效测试；采用 |
| 导出时查询当前业务表 | 读取简单 | 同一发布可能随当前数据变化，破坏不可变语义；不采用 |
| 建立全量历史事件存储并重放正文 | 历史查询能力强 | 引入新的持久化体系，超出本次交付缺口；不采用 |

采用第一种。若权威源不能解析批准版本，不自动读取最新版补齐；返回阻断错误，引导重新组装、批准新版本。已发布快照保持不变，不后台回填正文。

## 3. 正文契约

继续使用现有快照外层结构，在 `version_manifest` 添加 `body_schema_version: "graphrag.fmea.body.v1"`。无此标记的既有快照保持旧读取路径；新发布必须带该标记和有效正文。不更改旧快照的哈希或字节。

正文具有五个部分：

1. `rows`：保留 `row_id/record_version/row_hash`，新增 item/function、failure_mode、causes、mechanisms、effects、symptoms、controls、barriers、actions、原生状态、field_evidence、field_support、field_claims、typed extension_values。
2. `risk_records`：保留 assessment 身份与哈希，投影已确认的原生评分、规则身份、确认依据和行版本绑定。S/O/D/RPN 从已有记录读取，不在导出器重新打分；其他风险方法保持方法名与类型，不强制转换为 RPN。
3. `propagation`：已批准图身份、节点/边、边状态、证据引用和源行 lineage。没有传播时为 null，不制造空结论。
4. `evidence_summary`：pack 身份与哈希、被引用证据的 document ID/version、证据/内容哈希、允许公开的 locator 和原文 quote、source_type、source_trust。不导出凭证、私有路径、ACL 明细、模型原始响应或检索提示词。
5. `decision_summary`：批准决定及与所选行版本绑定的复核决定摘要；记录类型、ID、角色类别、决定、理由、时间、目标版本/哈希。没有原始复核决定时不得从 review_status 推造“谁何时确认”；新正文要求的记录缺失就阻断发布。

所有集合按稳定身份排序；未知、不适用、冲突、证据不足保持独立状态；空数组、null、空字符串不相互替换。扩展值必须来自绑定模板的声明式字段，保留命名空间、类型和值。decimal 不无条件转 float，沿用项目无损编码。

公开 locator 使用结构化定位：既有 `page:1#span:1` 可转换为 page/span 对象，标准来源的 canonical JSON locator 转为经安全校验的对象。原生 evidence_hash 在转换前验证；未知格式、URL、绝对路径、不安全成员不能通过改名或包装绕过限制。

为复核记录增加最小只读来源接口；只返回目标版本对应且可校验的公开字段和来源绑定，不扩大复核写权限。该接口具体实现与既有复核仓储复用，不能把整份运行审计全部复制进报告。

## 4. 版本、证据与事务安全

- 将来源对象的 workspace、analysis、对象 ID、版本、重算内容哈希与批准 revision 对比；重复、缺失、跨工作区、额外未批准记录均不能静默混入。
- 校验 EvidenceRef 原生内容与 evidence_hash，再校验 pack_hash 与逐字段引用；只比较调用方携带的哈希字符串不够。
- 复用已有来源证明和身份算法，不通过改写现有原生哈希算法达成兼容。
- 实施核对：HMAC 来源验证器封装在既有治理运行时闭包中。因此公开正文构建入口采用 `RuntimeGovernanceSource.build_publication_body()`，先验证来源，再调用应用层内部纯投影 `_project_publication_body()`；未配置的基础来源入口拒绝调用。纯投影不宣称提供来源权限，不能用调用方传入的 validator 或 proof 字段外观替代真实验证。此调整不改变外部发布请求。
- Task 1 复审修正：复核记录也必须从运行时配置的只读 `publication_reviews` provider 内部解析，公开正文入口不接受 `review_records`。未配置来源时拒绝构建；每行只选择一个精确版本对应的已接受人工决定。具体 SQLite 解析器在 Task 2 接入，不能由调用方声明自己是人工决定。
- 服务构建正文与发布前准备检查使用同一份受验证输入；不多次读取不同“当前状态”后拼接。
- 新增提交边界校验：准备的正文必须能与批准的权威源内容逐项核对。仅重算快照自身哈希、manifest 和审计链不能证明业务内容真实。
- SQLite 可变源在发布事务内重新核对版本/内容，禁止读取与提交之间的变化漏检；证据/注册表等独立来源须按固定内容身份解析并验证不可变内容。不能为跨存储对象虚构一个全局事务。若现有来源接口无法提供这些保证，Task 2 停止，不降级放行。
- 发布事务中任何故障均回滚快照、manifest、publication、eligibility、audit、outbox；原有幂等重放仍返回原发布，不重新生成正文。
- 导出只读取已保存快照；已发布后当前行变化不改变报告。撤销/替代沿用既有资格判断，不删除历史。

错误使用项目既有安全异常映射；正文专有错误拟定为 `FMEA_PUBLICATION_BODY_STALE`、`FMEA_PUBLICATION_BODY_INCOMPLETE`、`FMEA_PUBLICATION_BODY_UNSAFE`。不得向接口泄漏原文、路径或凭证。

## 5. 模板与报告表现

复用已编译模板及其固定身份，生成一个只读报告视图：声明式字段键、显示名、类型、次序、取值路径。禁止执行模板脚本、动态导入、任意文件访问和 URL 获取。

- JSON 保留完整机器可读快照和类型，不为了 Word 排版截断正文。
- XLSX 增加工程正文表：对象/功能、故障模式、原因、影响、检测/控制、措施、评分摘要、复核状态、证据编号；长证据、评分明细、传播和审核放独立表。保留现有可独立解码的类型表。
- DOCX 增加阅读正文和逐行详情；避免所有扩展字段排进同一张超宽表。保留机器可核对的附录，原文不悄悄截断。
- 可读视图中的检测/控制由模板映射到现有字段，不能声称系统已有独立 detection 字段或由模型自动补写。
- 中文显示名不改变 canonical field_key；未知扩展字段无损保留，非法路径明确拒绝；缺少显示配置时使用稳定键名，不填入猜测语义。
- 燃料、电气、软件均使用同一投影内核。普通 RAG、GraphRAG、combined 等仅影响 provenance/证据来源，不影响导出器业务分支。

## 6. 验收和非目标

最小交付例：燃料过滤器堵塞 → 当前既有生成/复核/评分/传播/批准/发布链路 → 三格式中能读到同一批准版本的实际正文和证据。数值沿用样例原生确认记录，不把样例当作真实工程推荐值。

验收需同时证明：

- 一次真实应用服务链路得到正文快照、Word、Excel、JSON；独立解码与原生批准数据相符。
- 改正文后重算所有导出层哈希仍不能骗过提交/独立验证。
- 行变更、证据篡改、角色冒充、复核记录错版本、失败回滚、幂等重放均覆盖必要反例。
- 旧摘要快照仍按旧合同读取；新快照不能通过删除正文标记伪装为旧结果。
- 电气/软件扩展字段保持类型与内容，不能只比较文件生成成功。
- Word/Excel 做实际可读性检查；内容一致测试不替代分页、列宽、中文和长文本检查。

不增加付费模型测试、检索质量基准、全领域安全认证、新 UI、新导出格式、任意 Office 模板编辑器或恒定内存承诺。真实资料/DeepSeek 试运行作为后续独立业务验收，不冒充本次离线质量证明。

## 7. 复核结论

本文及实施计划已获用户确认。特别需要保持的边界是：新正文合同、旧快照兼容、权威正文原子绑定、模板驱动显示、证据公开范围。实际完成项以实施计划中的测试及复审记录为准。
