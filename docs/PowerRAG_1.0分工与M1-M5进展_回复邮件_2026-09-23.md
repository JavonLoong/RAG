## 三、复原的 1.0 模块任务清单与初步分工

主线：

```text
资料获取（M1）
  → 解析/OCR/标注（M2）→ 候选资料
  → 审核入库（M3）→ 正式资料版本 + 检索
  → 图谱构建（M4）→ 正式图谱版本；质量不够回退 M3
  → 任务/FMEA（M5）→ 人审后发布、导出
  → 问题按根因回流 M1/M2/M3/M4
编排与验收（M6）贯穿全程
```

### 分工总表

| 模块 | 负责人（1.0） | 做什么 | 不做什么 |
|---|---|---|---|
| **M1 资料获取** | 资料负责人（现存摘录未写人名） | 把原始文件收进来并登记：来源、权限、密级、版本、能不能外发；收集、导入、版权/密级；缺页或 OCR 不够时补资料 | 不解析正文，不建检索库，不抽图谱 |
| **M2 解析与标注** | 纪文龙、丁河谷 | 把文件变成可定位的文本和结构；产出**候选资料**，给人对照原页审核 | 不直接当检索库，不发布正式版本 |
| **M3 资料库构建** | 纪文龙、张泽跃 | 把审过的资料做成正式版本：切片、关键词/向量/混合索引、引用、比较、作废、回滚、备份 | 不替代 M2 解析，不替代 M4 抽图 |
| **M4 图谱构建** | 纪文龙 | 只从**已发布资料**抽设备/部件/故障/原因/措施等，绑证据，发布图谱版本 | 图质量不够必须回退普通 RAG，不编无证据关系 |
| **M5 任务/FMEA** | 纪文龙 | 只从**已发布资料 + 已发布图 + 模板**生成 FMEA；字段带证据；人审后发布、导出 | 没有批准的评分政策，不算、不编 S/O/D、RPN |
| **M6 流程编排** | 张泽跃 | 固定 M1→M5、状态、批量、幂等、取消、重试、断点、质量门、版本链、验收报告 | 不重做各模块专业逻辑 |

### M1 资料获取

把原始文件收进来并登记：来源、权限、密级、版本、能不能外发。做的是收集、导入、版权/密级，不是解析内容。后面 OCR 出了问题，有时也要退回这里补资料。

1.0 里已写明的管理项：

- 登记资料来源、权限、密级和允许使用方式（含能不能外发）
- 识别重复资料及新旧版本
- 导入状态可查；文件收集、必要的网站抓取、版权审批、资料补齐
- 下游缺页、密级不够、不允许外发时，问题回流到本模块

### M2 解析与标注

把文件变成可定位的文本和结构：原生抽字或 OCR，保住标题、段落、页码、表格、图、阅读顺序，标质量问题，给人对照原页审核。产出是“候选资料”，不是检索库。

1.0 验收条：

- 按文件类型选择原生抽字、OCR 或外部版面解析
- 保住标题、段落、阅读顺序、表格、图片、图注
- 识别语言，保留原文；需要时做对齐译文
- 修复乱码、断句和基础结构，不得偷偷丢掉原文
- 标出缺页、低质量 OCR、表格错位
- 原页与结果对照复核
- 确认、否定、修改都留审核记录；改内容必须出新版本
- 单页失败、超时可回流、可重试

### M3 资料库构建

把审过的资料做成正式版本：切片、建索引（关键词 / 向量 / 混合）、能引用、能比较和回滚。这才是普通 RAG 用的那一层。

1.0 验收条（张泽跃交付说明与 8 月 8 日进度稿一致）：

- 一套规范资料模型；区分候选、待审、已发布、已作废
- 人工修改并入正式版本，历史不改写
- 切片仍绑页/块/表/图证据
- 建、更新、重建索引
- 关键词、语义、混合检索
- 基础 RAG 必须带引用；没有命中就说证据不足
- 版本比较、作废、回滚、增量更新、冲突保留、备份恢复

### M4 图谱构建（GraphRAG）

从已发布资料抽实体和关系（设备、部件、故障、原因、措施等），绑证据，发布图谱版本，供图检索和路径问答。图质量不够就回退到 M3 的普通检索。

1.0 验收条：

- 燃气轮机实体、关系、知识类型有版本化 Schema
- 抽设备、部件、故障模式、原因、影响、措施
- 别名、重复、型号差异、来源冲突要显式处理，不静默选边
- 每条关系绑所选资料版本中的证据
- 图谱可版本、查询、查看、导出
- GraphRAG 能展示路径；同题可与普通 RAG 对比
- 图质量不够时回退普通 RAG

### M5 任务 / FMEA 输出

从已发布资料 + 已发布图 + 模板生成 FMEA：故障模式、原因、影响、检测、措施，字段带证据，人审后再发布、导出 JSON/CSV/DOCX。不算分就不能编 S/O/D、RPN。

1.0 验收条：

- 请求、任务状态、错误和结果有稳定契约
- 必须指定资料版本、图谱版本、模板
- 最低燃气轮机 FMEA 模板
- 专业字段分别绑证据；缺证据保持为空并提示
- 多来源冲突要显示，不自动裁掉
- 人可批准、修改、否定、确认
- 发布后 JSON/CSV（及后来补上的 DOCX）与审核结果一致
- 问题按根因回流 M1–M4，并重新验证

### M6 流程编排

张泽跃在 1.0 中的另一半：

- 固定顺序：`m1_ingest → m2_parse_review → m3_publish → m4_graphrag → m5_fmea → m6_acceptance`
- 持久化运行状态、批量、幂等、进度、取消、自动重试、断点恢复
- 六道独立质量门和版本链校验
- 输出可归档的验收报告

| 模块 | 状态 | 已经能演示的 | 缺口 |
|---|---|---|---|
| M1 | 部分 | 源文件入库、SHA-256、重复预检、项目数据策略（涉密默认本地、外发要过策略） | 完整密级/版权/外发台账、抓取补资料工作流仍薄 |

| M3 | 可演示 | 审核发布、版本、关键词/向量/混合检索、引用、比较回滚、备份 | 正式 embedding 需在目标机配置并做真实检索验收 |
| M4 | 可演示 | Schema 约束、证据绑定、审核发布、路径问答、普通 RAG 回退 | 自动抽取依赖模型；燃机 Schema 待领域签字 |
| M5 | 可演示 | 从已发布图生成、逐字段证据、审核发布、JSON/CSV/DOCX | 禁止无政策编分；电动机模板未单独验收 |

## 五、给非开发同事的一句话对照

**收文件（M1）→ 读懂并标好（M2）→ 做成可检索资料库（M3）→ 做成可追问的图谱（M4）→ 按任务吐出可审核的 FMEA（M5）**

旁边的 M6 负责让这五段按顺序跑、失败能重来、版本对得上、最后有验收报告。
