# Phase 4 Task 7 工作台验证记录

日期：2026-09-04。基线：`ef3b240356b0c2edea68065d0f4982eb96f4a4b0`，分支：`feat/interface-output-v1`。

范围是本地 FMEA 浏览器工作台，不是 Phase 4 全产品验收。Task 7 实现、定向验证和三组复审已收口。

## 交付范围

- 原生 HTML/CSS/JavaScript，复用现有静态服务，不增加前端框架或另一套领域引擎。
- 八个入口：分析、证据、字段复核、风险评分、传播分析、批准发布、模板与迁移、成果导出。
- 同源 REST 客户端负责内存令牌、真实 ETag、幂等键、不透明游标、错误信息和 HTTP 中止；领域规则、鉴权和持久化仍由后端负责。
- 显式确认对话框显示目标分析、行、修订、资源版本和请求内容；模型建议与人工决定分开显示。
- 成果下载按服务端制品身份核对摘要和文件名；模板上传限 XLSX/DOCX、256 KiB，并保持草稿/建议/人工决定分离。
- 唯一后端行为增量：迁移 dry-run 响应增加服务端生成的 `report_id` 元数据。原有报告内容哈希不变，未新增虚构的报告 GET 接口。

## 定向修复

1. 手工查询风险运行 B 时消费 B 的 GET 结果，不被此前运行 A 的 POST 缓存遮蔽。
2. 发布后按成功回执中的 publication_id 刷新；拒绝审批不显示已批准审批的撤回入口。
3. 模板接受/拒绝后消费同草稿的规范 GET 决定与新版本；导入新草稿不沿用旧草稿补丁。
4. 迁移确认后按真实 child_revision_id 刷新子修订，展示回执，不请求不存在的报告 GET。
5. 网络未知、HTTP 中止和服务端明确可重试错误保留原请求与幂等键；未决写入阻止连接重置和另一次写入。
6. 写入成功与后续读取失败分开处理；读取重试不重新 POST。复核建议入口在创建新 operation 前也检查未决写入。
