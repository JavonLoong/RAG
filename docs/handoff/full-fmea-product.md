## 产品范围与已实现能力

FMEA 是 RAG Skill 的可迁移业务子系统，不另建检索引擎。上游交付不可变 EvidencePack、检索来源与版本；FMEA 负责候选、逐字段证据、人工复核、风险评分、传播复核、版本审批、发布与交付。RAG / GraphRAG / combined / auto 选择沿用上游合同。

Phase 4 在已有风险、传播、治理能力上完成以下交付层：

| 能力 | 具体实现 | 约束 |
| --- | --- | --- |
| Excel/Word 模板导入 | 安全解析表头、表格和原始结构，生成带源哈希的 TemplateDraft | 导入不等于注册；拒绝公式、危险 Office 内容 |
| 大模型辅助改模板 | 生成有界字段映射/补丁建议，保存不可变建议和决定 | 模型不能注册模板或假扮人工管理员 |
| 人工接受与注册 | template_admin 接受后，经真实编译器及不可变注册表登记新版本 | 领域包、模板、评分规则分别绑定版本与哈希 |
| 显式迁移 | allowlist 适配器、兼容性报告、dry-run、人工确认、子版本 | 不改写父发布版；清除子版本旧风险和传播引用，必须重新复核 |
| 三格式导出 | 同一 NormalizedFmeaSnapshot 派生 JSON、XLSX、DOCX，文件清单与哈希校验 | 显示 Identity 与实际表格内容均需一致 |
| 交付持久化 | SQLite 幂等预留、执行记录、审计、outbox、原子产物目录 | 重试不重复产生业务副作用 |
| REST / CLI / Skill | 交付合同、模板与迁移操作、导出及下载 | 调用者使用接口，不直接访问数据库 |
| 浏览器工作台 | 原生 ES Modules + REST；证据、复核、评分、传播、审批、模板、迁移和导出页面 | 区分建议/人工、草稿/审批/发布；没有擅自添加上游资源发现接口 |
| 可迁移性与验收 | 燃料/燃烧、电气、软件三个结构不同的领域包，独立验收器与万行样例 | 电气/软件证明结构复用，不宣称完整领域工程认证 |

## 完整离线样例实际执行了什么

入口：`scripts/run_fmea_full_acceptance.py`。确定性网关只替代模型输出；之后调用真实应用服务、不可变注册表和同一个临时 SQLite 数据库，不预填已确认/已审批状态。

1. 按既有查询合同选择离线燃料滤清器 EvidencePack，生成候选并持久化。
2. 生成字段复核建议，人工接受；当前行从 v1 到 v2，原始来源快照仍保持 v1。
3. 提议并人工确认 S/O/D=8/3/4，由真实服务计算 RPN=96。
4. 使用真实燃料拓扑/传播规则提出 `fuel_filter → fuel_manifold`，人工复核接受，保存逐边证据与源行版本/哈希。
5. 真实组装父版本与另一个治理子版本，分别人工审批、发布，各运行 JSON/XLSX/DOCX 导出，共六个文件。
6. 导入新的普通 Excel 模板，大模型给映射补丁，人工接受后由默认源码构建器编译/注册模板 v2。
7. 对原始父版本执行迁移 dry-run 和人工确认，生成第三个、待复核的迁移子版本。它不是上一步已发布的治理子版本，不能自动继承发布资格。
8. 执行治理子发布替代父发布，再撤销子发布；原始历史保留。
9. 重放受保护命令，收集真实返回值、审计、outbox 和前后计数；传播重放额外对持久化全表内容计算状态哈希，避免只比较数量。

传播中的 `fuel-filter-1 → fuel_filter` 是样例只读映射，数据库行 ID 不变。拓扑邻居查询委托真实 JsonTopologyRepository。源行 lineage 证明本次实际网关输入，不宣称因此增加了生产环境的原子失效/并发契约。

导入源是独立的 `inputs/template.xlsx`，不是演示导出的排版 XLSX。排版文件含打印区域 defined-name，严格导入器会拒绝；本轮没有放宽安全规则来做无要求的排版文件回灌。

## 版本衔接修正

实际链路发现：人工复核更新当前行到 v2，但来源快照应保持 v1。修正 `risk_repository_sqlite._validate_sources` 后，评分仍严格检查当前行 CAS/哈希；来源快照独立核对自己的存储版本、工作区与哈希，并禁止来源版本晚于评分行。历史读取也禁止评分提案引用高于当前行的版本。

该修正已经过定点独立复审；没有重写历史来源、移除防篡改或修改传播分析聚合版本列。

## 产物与独立验证

公开验收目录仅包含：

- `manifest.json`：schema、run ID、文件清单、字节长度、SHA-256 和待复核的 P0 汇总。
- `evidence.json`：实际 DTO、步骤/重放记录、版本关系、审计/outbox、领域注册证明。
- `exports/`：两个已发布快照对应的六份 JSON/XLSX/DOCX。
- `inputs/template.xlsx`：绑定导入草稿源哈希的普通模板。

私有运行数据库和注册表不复制到公开包。新包先写入独立 pending 目录，验证成功后原子改名并更新 `latest.json`；失败不推进 latest，保留 pending 供诊断。

独立校验器不导入 runner、测试夹具或导出器投影函数。它检查精确文件清单、原生哈希、版本/审批/发布/导出绑定、人工权限、步骤和迁移失效关系，并独立解码 XLSX/DOCX 与原始快照逐项比较。四项 P0 计数从原始数据计算，不能信任 manifest 自填零：

- 模型审批/发布；
- 声称已知但没有有效证据；
- 人工确认了无效评分；
- 接受高风险却没有证据的传播边。

矩阵最初暴露两个旧 MigrationReport 测试缺少已新增必填字段，以及负向 `--latest` 测试依赖开发机默认目录为空；修正后当时为 548 passed、3 skipped。随后发现安全夹具依赖本机临时产物，会在其他机器跳过：现改为每模块在 pytest 临时目录实际生成一次完整包，不硬编码路径、不因缺少开发机产物跳过。传播 lineage 也从可选改为必须提供。52 项和 65 项是中间增量证据，最终 563 项已覆盖这些修正与反例，数量不相加。

Windows 门禁的 3 项跳过对应 POSIX flock / 本机 symlink 能力场景，不宣称在 Windows 运行了真实 POSIX 进程锁。重复 ZIP 成员攻击样例产生一条预期 UserWarning。跨平台真机锁验证仍由相应平台承担。

正式产物包含 30 个步骤、21 条重放记录、3 个版本、2 次发布、6 个导出文件、2 条传播源行 lineage，以及 24 条业务审计、3 条模板审计和 24 条 outbox。电气/软件的三领域结构证明仍与燃料完整生命周期分开标注。

整体复审曾发现“单项合法但跨对象不一致”仍被接受：当前行/评分与版本哈希、伪造空重放回执、迁移目标完整身份、传播拓扑与内容、导出运行元数据，以及撤销/替代状态。已增加对应的独立内容重算、事件绑定及负例检查；65 项是这轮修复的增量证据，仍不与之前测试数量相加。

特别说明：沿用的治理发布快照中，行、评分、传播是 ID/版本/内容哈希摘要，因此本次真实发布的三格式文件也是身份摘要视图；详细故障字段、逐字段证据、评分与传播 DTO 保存在同一公开包的 `evidence.json`。三格式适配器能保留丰富字段（跨域测试另有验证），但把已有治理发布器升级为丰富正文快照不属于本次六项 verifier 修复，不能将此身份摘要样例描述为已完成排版的工程 FMEA 正文报告。

## 复现

在本分支工作树根目录运行：

```powershell
.venv\Scripts\python.exe scripts/run_fmea_full_acceptance.py
.venv\Scripts\python.exe scripts/verify_fmea_full_acceptance.py --latest
```

运行含 API 合同的 pytest 矩阵或启动工作台时，先按仓库既有方式设置当前进程的源码路径：`$env:PYTHONPATH = "api_server/current_console/chroma_rag_poc/src"`。根项目并不打包这个独立 API 子项目；无需因此安装其全部检索/模型依赖。

默认输出：`observability/reports/fmea-full-acceptance/<artifact_id>/`。也可用 runner 的 `--output-root` 指定新目录，再把生成的实际目录传给 verifier。执行失败应检查安全错误码及对应 pending 包，不应手改零计数或 latest 伪造成功。

## 可迁移性与后续接入边界

新领域通常新增声明式 DomainPack、模板/字段映射、评分锚点与证据材料；破坏性变化需要显式 allowlist 迁移适配器。燃料包不改原 manifest 哈希；电气包增加 decimal 电压/电流与隔离字段，软件包增加功能、危险行为、触发和检测字段，通用内核不导入这些领域模块。

万行验证使用真实三格式导出和独立解码，并观测 100 页、每页 100 行。JSON 新增可选 `iter_chunks`，保持既有 `render` bytes 合同与输出哈希，详见 [JSON 分块接口](fmea-json-chunks.md)。有界输出块不等于整个过程恒定内存：快照、归一化投影、Office 库和原有 ExportService 仍可能完整物化数据。

离线样例不调用外部 API、不产生模型费用；它验证应用合同，不验证真实 DeepSeek 质量、上游检索召回率、所有领域的评分适用性或工业安全性。接入真实资料/模型需另做有代表性的业务验证。被迁移清空的评分和传播需要重新提议、人工确认、审批、发布。
