1 社区划分 (Community Detection)

📄 kg_pipeline/community_detection.py · 算法: Leiden (leidenalg + igraph)
加载图谱数据
从 SQLite GraphStore 读取全部节点和边
graph_store.get_all_nodes()
graph_store.get_all_edges_as_tuples()
→
构建 NetworkX 图
将节点/边转换为 NetworkX 无向图,合并多条边权重
build_networkx_graph()
→
转换为 igraph
将 NetworkX 图转换为 igraph 格式,保留节点名和边权重
igraph.Graph(n=len, edges=...)
→
运行 Leiden 算法
使用 RBConfigurationVertexPartition 做社区划分,支持 resolution 参数控制粒度
leidenalg.find_partition(ig, resolution=1.0)
→
生成社区分配
为每个节点分配社区 ID (如 C0, C1, C2…) 并统计社区大小
CommunityAssignment(node, C0, level=0)
→
持久化写入 DB
将社区分配结果写回 SQLite 的 communities 表
graph_store.store_communities()

2 主题摘要 (Community Summarization)

📄 kg_pipeline/community_summary.py · 依赖: LLM Client + GraphStore
读取社区列表
从 DB 获取指定 level 的全部社区,过滤 member_count < min_size 的小社区
graph_store.get_communities(level=0)
→
提取社区实体与边
获取每个社区内所有实体名称和三元组关系
get_community_entities(C0)
get_community_edges(C0)
→
构建摘要 Prompt
将实体列表和关系列表格式化为 LLM 可理解的结构化文本
build_community_prompt()
→
调用 LLM 生成摘要
要求 LLM 返回 JSON: {"title": "...", "summary": "..."}
_call_llm(llm, prompt)
→
证据溯源绑定
将摘要中每个句子匹配回源三元组 ID,建立 sentence_evidence 映射
build_summary_sentence_evidence()
→
写入摘要表
持久化 title, summary, entity_count, metadata 到 community_summaries 表
store_community_summaries()

3 证据召回 (Evidence Retrieval & Routing)

📄 rag_orchestrator/router.py + retrieval_engine/graph.py + rag_orchestrator/global_search.py
用户输入 Query
接收用户的自然语言问题
→
语义分析 + LLM 路由
先用规则分析器 SemanticQueryAnalyzer 判断,再用 LLM 做精确分类
AdaptiveQueryRouter.route_query()
→
路由决策输出
VECTOR_ONLY LOCAL_SEARCH GLOBAL_SEARCH
🔍 局部搜索 (Local Search)
  • 文本召回: ChromaDB 向量相似度 TopK
    text_retriever.retrieve(query, top_k)
  • 图谱召回: 实体名 N-gram 匹配 → PPR 多跳 BFS 遍历邻居
    SQLiteGraphRetriever.retrieve()
  • PPR 评分: score = match_score × confidence × 0.85^hop
  • 社区摘要: 关键词命中 community_summaries 表
🌐 全局搜索 (Global Search — Map-Reduce)
  • MAP 阶段: 遍历每个社区摘要, LLM 判断是否相关并产出 Partial Answer
    GlobalSearchOrchestrator.search()
  • 过滤: LLM 返回 "NOT_RELEVANT" 则跳过
  • REDUCE 阶段: 将所有 Partial Answers 合并, LLM 综合输出最终答案
  • 溯源: 每个 Partial Answer 携带 source_evidence (triple_id + 原文)

4 推理生成 (Inference & Answer Generation)

📄 rag_orchestrator/graphrag_qa.py · GraphRagQAOrchestrator
多源证据合并
将文本证据 [T1..TN]、图谱证据 [G1..GN] 和社区证据 [C1..CN] 合并
build_context(question, text_ev, graph_ev, global_ctx)
→
构建推理 Prompt
将合并上下文 + 引用 ID 列表 + 用户问题组装为 Prompt
build_default_prompt(q, ctx, citations)
→
LLM 生成答案
调用 LLM 生成带 [T1] [G2] 等引用标记的自然语言回答
_call_llm(self.llm, prompt)
→
幻觉检测 (可选)
HallucinationGuard 检查答案中是否有证据不支持的声明
hallucination_guard.verify(answer, context)
→
自修正循环
若检测到幻觉, 重新构建带修正指令的 Prompt, 最多重试 3 次
max_retries = 3
→
输出最终结果
返回 GraphRagQAResult: answer, citations[], evidence[], prompt
GraphRagQAResult.to_dict()

5 结果评估 (Evaluation & Quality Gate)

📄 evaluation/quality_profiles.py · evaluation/harness.py · evaluation/metrics.py
加载评测题集
读取 system_eval_questions.jsonl 中的标准问答对 (question + ground_truth)
system_eval_questions.jsonl
→
批量运行 QA
对每个问题分别跑 RAG 和 GraphRAG 管线, 捕获 answer + citations
runner.py batch_evaluate()
→
计算评测指标
召回率 Recall, 精确率 Precision, 事实一致性 Faithfulness, 引用覆盖
metrics.py
→
质量门禁检查
综合评分是否达到 quality_profiles 中定义的最低通过线 (如 90%)
benchmark_quality_gate.py
→
生成评测报告
输出 Markdown/HTML 评测报告, 含 RAG vs GraphRAG 对比表和失败归因
evaluation/reports/
