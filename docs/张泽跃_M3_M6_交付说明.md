# 张泽跃负责模块 M3 / M6 交付说明

## 1. 交付边界

本交付只实现任务清单中张泽跃负责的两部分：

- M3：审核后资料的规范化、修订状态、发布版本、证据切片、关键词/语义/混合检索、基础 RAG 引用、比较/作废/回滚、备份恢复。
- M6：M1→M5 固定流程、持久化运行状态、批量运行、幂等、进度、取消、自动重试、断点恢复、独立质量门、版本链校验和验收报告。

M1、M2、M4、M5 的专业实现仍由对应模块负责。本交付通过 `DocumentInput`、`PowerRagHandlers` 和稳定 JSON 输出契约连接它们，不复制或篡改其他模块逻辑。

## 3. M3 资料库设计

### 3.1 生命周期

```text
candidate → pending_review → approved review → published
     ↑              │                              │
     └── rejected ──┘                              └── deprecated
```

- 修订内容一旦创建即不可变；修改必须产生新修订。
- 同一 `document_id + content_sha256 + pipeline_fingerprint` 重复提交会返回原修订，避免重复切片和向量化；切片参数改变则生成新修订，支持可审计的索引重建。
- 发布不是修改一个“当前”标志，而是创建完整资料快照、父版本和 manifest SHA-256。
- 作废和回滚也创建新版本，历史版本永不被改写。
- `expected_base_version` 提供乐观并发控制，防止两名发布者互相覆盖。

### 3.2 规范资料结构

```text
Document
├─ Revision
│  ├─ Page
│  │  ├─ Block (title / paragraph / table text / caption...)
│  │  └─ Asset (table / image → URI + checksum)
│  └─ Chunk
│     └─ EvidenceLocator(page, block, char_start, char_end)
└─ Release(version → document revision snapshot)
```

每个检索结果都返回资料版本、文档修订、来源 URI、页码、区块和字符范围。M4 图谱关系、M5 FMEA 字段可直接保存 `chunk_id` 及其证据定位，不需要从答案文本反推来源。

### 3.3 检索与向量化

- 关键词索引使用 BM25，并同时索引英文词、中文单字和中文双字，避免 SQLite 默认分词器把整段中文视作一个词。
- 向量以 `chunk_id + embedding_model` 版本化；内容哈希未变化时跳过，支持增量更新和模型并存。
- `index-embeddings --force` 可在模型实现或服务参数变化但模型名不变时强制重建。
- 语义检索使用余弦相似度；混合检索使用 Reciprocal Rank Fusion，避免 BM25 和向量分数的量纲不同导致排序偏置。
- `KnowledgeBaseRetriever` 已实现仓库现有 `BaseRetriever` 协议，可被现有 query/GraphRAG 编排直接注入。
- 基础 RAG 固定使用已发布版本；无命中时明确返回“证据不足”，不会让生成器自由补造。
- 查询可传入 `allowed_access_labels`；资料修订中的 `required_access_labels` 不满足时不会进入检索上下文。
- 多来源材料可在修订 metadata 中使用同一 `conflict_group` 显式标记冲突，RAG 返回并列冲突证据，不自动裁决。

生产发布建议使用适合中英文技术资料的真实 embedding 模型。`hashing-test-only` 只用于离线测试，不能作为语义效果结论。

## 4. M6 流程与质量门

固定流程为：

```text
m1_ingest
→ m2_parse_review
→ m3_publish
→ m4_graphrag
→ m5_fmea
→ m6_acceptance
```

每一步都有独立持久化状态、尝试次数、输入/输出、错误、质量门结果和检查点。进程在某一步为 `running` 时退出，再次执行会把该步识别为中断并在剩余重试预算内恢复。

| 门 | 阻断条件 |
| --- | --- |
| M1 无静默丢失 | 接收数不等于登记数+失败数，或存在失败文件 |
| M2 证据与审核 | 未批准、证据覆盖率不足 100%、仍有阻断问题 |
| M3 版本完整性 | 无资料版本、manifest 非 SHA-256、版本质检失败 |
| M4 图谱/回退 | 图谱证据覆盖不足且基础 RAG 回退不可用 |
| M5 FMEA 审核证据 | 未审核/发布、字段证据不足 100%、无成果版本 |
| M6 版本链 | 图谱或 FMEA 使用的资料版本与 M3 发布版本不同 |

工作流支持：

- `idempotency_key`：同输入重复请求返回同一运行；同 key 不同输入直接冲突。
- `start_batch`：按批次前缀生成一组可独立追踪的运行。
- `request_cancel`：步骤间立即取消；长步骤通过 `context.raise_if_cancelled()` 协作取消。
- `RetryableStepError` 与 `max_attempts`：故障注入和瞬时失败自动重试。
- `save_checkpoint/load_checkpoint`：外部任务 ID、页游标或增量水位可跨进程恢复。
- `retry_failed`：质量问题修复后由操作者显式重开失败/阻断步骤。
- `workflow_report`：输出 `power-rag.workflow-report.v1` 验收证据。
- 运行错误在持久化前会脱敏 API key、token、password、Bearer 凭据和 Windows 绝对路径。

## 5. 操作手册

### 5.1 初始化与候选资料

```powershell
python scripts/knowledge_base_cli.py --db storage_layer/runtime/knowledge_base.sqlite3 init
python scripts/knowledge_base_cli.py --db storage_layer/runtime/knowledge_base.sqlite3 create-candidate `
  --input configs/knowledge_base.example.json --actor m2-parser
```

保存返回的 `revision_id`，然后提交并记录人工审核：

```powershell
python scripts/knowledge_base_cli.py --db storage_layer/runtime/knowledge_base.sqlite3 submit-review `
  --revision REVISION_ID --actor m2-parser
python scripts/knowledge_base_cli.py --db storage_layer/runtime/knowledge_base.sqlite3 review `
  --revision REVISION_ID --decision approved --reviewer domain-reviewer
```

### 5.2 向量化与发布

本地模型示例：

```powershell
python scripts/knowledge_base_cli.py --db storage_layer/runtime/knowledge_base.sqlite3 index-embeddings `
  --revision REVISION_ID --backend sentence-transformer --model BAAI/bge-m3
python scripts/knowledge_base_cli.py --db storage_layer/runtime/knowledge_base.sqlite3 publish `
  --revision REVISION_ID --actor m3-publisher --require-embeddings --embedding-model BAAI/bge-m3
```

OpenAI 兼容 embedding 使用 `--backend openai`，密钥只从 `OPENAI_API_KEY` 读取，命令和日志不会输出密钥。

### 5.3 检索、质检和回滚

```powershell
python scripts/knowledge_base_cli.py --db storage_layer/runtime/knowledge_base.sqlite3 search "压气机积垢如何处理" --mode keyword
python scripts/knowledge_base_cli.py --db storage_layer/runtime/knowledge_base.sqlite3 verify --version 1 `
  --require-embeddings --embedding-model BAAI/bge-m3
python scripts/knowledge_base_cli.py --db storage_layer/runtime/knowledge_base.sqlite3 compare --from-version 1 --to-version 2
python scripts/knowledge_base_cli.py --db storage_layer/runtime/knowledge_base.sqlite3 rollback `
  --target-version 1 --expected-base-version 2 --actor m3-publisher
```

### 5.4 备份恢复

备份会同时生成 SQLite 文件和包含 SHA-256/资料版本的 manifest。恢复前强制校验文件名、SHA-256 和 SQLite 完整性。

```powershell
python scripts/knowledge_base_cli.py --db storage_layer/runtime/knowledge_base.sqlite3 backup `
  --output-dir storage_layer/backups --name kb-before-rebuild
python scripts/knowledge_base_cli.py --db storage_layer/runtime/recovered.sqlite3 restore `
  --backup-db storage_layer/backups/kb-before-rebuild.sqlite3 `
  --manifest storage_layer/backups/kb-before-rebuild.manifest.json
```

## 7. 设计依据

- [Microsoft GraphRAG Inputs](https://microsoft.github.io/graphrag/index/inputs/) 使用内容哈希获得跨运行稳定文档 ID；本实现同样用规范内容哈希保证幂等。
- [Microsoft GraphRAG Outputs](https://microsoft.github.io/graphrag/index/outputs/) 把 Document、TextUnit 及其实体/关系引用作为知识模型；本实现将 chunk 与页/区块证据绑定，直接供 M4 使用。
- [LlamaIndex Ingestion Pipeline](https://docs.llamaindex.ai/en/stable/module_guides/loading/ingestion_pipeline/) 的文档管理维护 `doc_id → document_hash` 并对变更内容增量处理；本实现将该原则扩展到审核修订与向量模型版本。
- [Qdrant Migration and Recovery](https://qdrant.tech/documentation/migration-recovery-options/) 建议用已校验快照恢复到已知良好状态；本实现为本地 SQLite 生成带 checksum 的备份 manifest。
- [Apache Airflow Tasks](https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/tasks.html) 将任务、依赖、状态和重试作为工作流基本单元；[Task State Store](https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/task-and-asset-state-store.html) 强调检查点应跨重试/崩溃持久化。本实现采用相同工程原则，但保持为项目内轻量运行时。

## 8. 已知边界

- 当前运行时面向单机/课题组本地部署；多节点调度、租约和分布式锁应交给 Airflow、Temporal 等平台，不在一期范围。
- SQLite 内置向量扫描适合当前资料规模和可验证原型；百万级 chunk 应保持相同契约并替换为 Qdrant/pgvector 等服务。
- embedding 质量取决于实际模型；离线测试向量只验证工程路径，不证明召回效果。
- M4 图谱质量和 M5 FMEA 专业正确性仍需对应负责人及领域审核人给出金标和人工结论。
