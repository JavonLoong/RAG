# M2 OCR 百度云与本地验证结果

> 验证日期：2026-08-11<br>
> 分支：`codex/8.8汇报`<br>
> 数据边界：只使用程序生成且 `external_allowed=true` 的合成页，没有上传项目内部资料

## 一句话结论

本地 RapidOCR、百度通用标准版和百度通用高精度版在本轮合成页上的文字结果完全一致；真正的短板不是“认字”，而是表格行列结构和双栏阅读顺序。百度表格文字识别 V2 已恢复表格结构，百度办公文档识别和本地分栏后处理都把双栏 CER 从 `0.6160` 降到 `0.0000`。

## 已完成能力

- 统一的本地/百度 OCR 适配器、清单和评估报告；
- 云端外发门禁：只有 `external_allowed=true` 才允许调用百度；
- 本地 RapidOCR 3.8.4 + ONNX Runtime 1.24.4 基线；
- 百度 `general`、`accurate`、`office`、`table` 四类真实接口验证；
- CER、置信度、耗时、双栏顺序、表格结构和人工复核标记；
- 原始框顺序与重排候选同时保留，不用优化结果覆盖原始证据；
- API Key、Secret Key 和 access token 不进入代码、报告或提交记录。

## 实测结果

| 场景 | 本地 RapidOCR | 百度通用标准版 | 百度通用高精度版 | 专用接口结论 |
|---|---:|---:|---:|---|
| 清晰正文 CER | 0.0000 | 0.0000 | 0.0000 | 不需要云端兜底 |
| 低清正文 CER | 0.0000 | 0.0000 | 0.0000 | 不需要云端兜底 |
| 表格文字 CER | 0.0000 | 0.0000 | 0.0000 | 三者都能认字，但通用接口没有行列结构 |
| 双栏原始顺序 CER | 0.6160 | 0.6160 | 0.6160 | 三者都按同一水平线左右交替输出 |
| 双栏重排候选 CER | 0.0000 | — | — | 本地坐标重排和办公文档分栏均可恢复为 0.0000 |
| 表格结构 | 无 | 无 | 无 | `table` 与 `office` 均返回 1 张表和单元格行列坐标 |

百度表格文字识别 V2 在合成表格页上返回：

- `table_num=1`；
- 16 个表体单元格；
- 每格的 `row_start`、`row_end`、`col_start`、`col_end`；
- 表格文字 CER `0.0000`；
- 本轮云端耗时约 `1.38 s`。

百度办公文档识别在合成双栏页上返回：

- `sec_rows=1`、`sec_cols=2`；
- 2 个栏区域和 9 个版面块；
- 原始行顺序 CER `0.6160`；
- 按百度分栏坐标重排后 CER `0.0000`；
- 本轮云端耗时约 `0.45 s`。

通用标准版四页云端耗时为 `1.4890 / 0.2436 / 0.2756 / 0.2439 s`；高精度版为 `1.2039 / 0.3983 / 0.3461 / 0.3428 s`。首个请求包含获取令牌等冷启动影响，因此这些数字只用于本轮工程对比，不能当作正式 SLA。

## 推荐路由

```text
页面进入 M2
  ├─ 普通正文、置信度合格 → 本地 RapidOCR
  ├─ 双栏/复杂版面
  │    ├─ 不允许外发 → 本地坐标分栏重排 + 人工复核
  │    └─ 允许外发 → 百度 office + 人工复核
  ├─ 表格
  │    ├─ 不允许外发 → 本地文字 + 表格结构待人工/本地模型补齐
  │    └─ 允许外发 → 百度 table，保留单元格行列坐标
  └─ 低置信度或结果冲突 → 人工金标/复核，不自动覆盖原文
```

不建议全量调用高精度版：本轮高精度版没有降低 CER。它可以作为低置信度页的复核选项，而不是默认路径。

## 当前评分

按“可以演示、可以复现、具备安全门禁和证据，但还没有真实项目金标验收”的标准，M2 OCR 当前可评为 **8/10**。

得分来自：真实云接口打通、四类分层测试、结构化表格、双栏优化、外发策略、报告与自动测试。未到 10 分的原因是：

1. 当前准确率结论来自合成页，不能替代真实扫描资料；
2. 还没有 20—50 页经负责人批准外发并完成人工逐字校对的真实金标；
3. 表格/办公文档路由尚未接入批量生产任务和人工审核界面；
4. 尚未根据真实错误建立术语纠错表或决定是否训练本地模型。

## 汇报演示顺序（3—5 分钟）

1. 展示清晰正文：本地和百度文字都正确，说明基础 OCR 已可用。
2. 展示双栏原始结果：故意让大家看到左右交替，说明“CER 高不是错字，而是阅读顺序错”。
3. 展示分栏重排结果：CER 从 `0.6160` 降至 `0.0000`，且原始框未被覆盖。
4. 展示表格 V2 JSON：指出 16 个单元格及行列坐标，说明结果可直接进入 M3/M4，而不是一串换行文字。
5. 最后展示安全门禁：内部资料默认不上传，只有获得许可的页面才调用云端。

## 下一阶段验收

1. 由资料负责人选择 20—50 页可外发真实样本，覆盖正文、低清、双栏、表格、页眉页脚和公式。
2. 人工制作逐字金标和表格单元格金标，固定样本版本与 SHA-256。
3. 分层计算 CER、表格单元格准确率、阅读顺序准确率和人工复核率。
4. 达到门槛后，把路由策略接入 M2 批处理；未达到门槛时优先改版面和预处理，不盲目微调识字模型。
